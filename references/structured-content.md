# 结构化内容：先确定可翻译范围

用户指定的格式契约优先。保留机器语义，翻译面向人的文字；字段名或文件扩展名只能提供线索，不能证明每个字符串都可翻译。严格 JSON、JSONL、字幕等交付物内不得夹带注释或外层 Markdown 围栏。

## Markdown / MDX

- 保留标题层级、列表嵌套、表格列数、引用、脚注标识及定义。翻译表格时转义会被当作分隔符的 `|`。
- 翻译链接标签和图片替代文本，保持目标地址、文件路径和显式锚点。标题翻译可能改变自动生成的锚点：检查目录与内部引用；按项目惯例保留稳定锚点或同步内部引用，并验证目的地。若用户要求逐字保持链接目标且无法兼容，说明这一冲突。
- 代码围栏的语言标签、围栏类型及足以包住内容的长度保持有效。可执行代码默认保留；围栏里明确指定待译的纯文本仍应翻译。
- 只在用户要求或项目明确约定时翻译代码注释、文档字符串和用户可见字符串。区分日志协议、测试快照和普通提示语，保护转义及插值。
- MDX 的组件名、导入、表达式和属性语法不是正文；只改明确供展示的内容。Frontmatter 同理。

## JSON / JSONL

- 默认保留键名、对象/数组层级、元素数量、数值、布尔值、`null` 和机器标识。
- 按用途翻译字符串值。可见的 `title`、`description` 常可翻译；`id`、`slug`、`url`、`path`、枚举值和协议消息通常保留。不要凭键名替代语境判断。
- 正确转义引号、反斜线、控制字符；禁止尾随逗号和注释。JSONL 每一行都应独立可解析，不合并记录。
- 尽量维持原有排版、键顺序与数字字面形式，尤其不要在重新序列化时默默改变大整数、有效位或重复键。
- 例：`{"message":"Welcome, {name}!","count":2}` → `{"message":"欢迎，{name}！","count":2}`。
- 有工具时解析最终产物，并对照结构与受保护字段。解析成功不证明翻译范围或语义正确；本仓库的结构检查同样不能自动识别所有不可翻译字符串。

## YAML / TOML / INI

保留缩进、键、类型、插值和语法。引号、冒号、`#`、多行标量等可能改变值的解析方式；翻译后使用对应格式的解析器验证（若环境具备）。不要将 `true`、`null`、端口或环境变量译成中文；不因 YAML 看起来像文本而随意解除引号。

## HTML / XML

翻译可见文本及明确可翻译的 `alt`、`title`、`aria-label` 等展示值。保留标签、层级、属性名、`id`、`href`、`src`、模板表达式及脚本/样式内容。尊重 `translate="no"` 或项目定义的不可翻译区域。实体与字符均可承载同一文本，但不得无依据改写编码或破坏标记。

## 字幕 SRT / WebVTT

保留 cue 顺序、标识、时间码、时间范围、样式/位置设置和有效空行；WebVTT 的头部、STYLE/REGION 等不是字幕正文。仅翻译字幕及需要本地化的说话人标签。用户给出行宽、时长或阅读速率约束时检查约束，不能无声删掉关键含义来达标。未获重新计时授权时不调整时间轴。

## LaTeX 与数学

保留命令、公式、标签、交叉引用和定界符。翻译正文以及确定用于显示的文字参数；不要把所有花括号内容都当成普通文本。数学中的负号、小数点、百分号及运算关系具有语义，中文排版不能覆盖它们。

## 占位符与消息模板

- 保留名称、数量、格式限定符、大小写和转义。包括 `{name}`、`{{name}}`、`${USER}`、`%(name)s`、`{0:.2f}`、`%1$s`、`%%` 等。
- 命名/带位置的参数通常可以随语序重排；无位置的 `%s`、`%d` 等依赖参数顺序，不能只保证数量一致。
- ICU MessageFormat 要保护参数、`plural/select/selectordinal` 语法、选择键、`offset`、`#` 与嵌套边界。只翻译分支消息，不擅自删除看似多余的复数分支；地区规则改写须作为明确的本地化任务并经解析/运行验证。
- 路径、命令选项、变量名及 API 标识按机器用途保护；不能靠“看起来像英文”判断可翻译。

机械检查对复杂模板、Markdown、字幕和不同解析器方言并不完备。结合原文与目标格式确认每个报告项，不能以零发现代替格式验证。
