# 翻译质量：语义复核与机械检查分开

这里使用准确性、术语、语言、文体、地区约定和标记等实用分类。这是项目的审校规则，不是认证标准或经验证的量化评分模型。

## 可定位的错误

| 分类 | 重点 |
| --- | --- |
| 准确性 | 主体、归属、时间、否定、情态、条件、范围、证据强度、遗漏与无据增译 |
| 术语 | 概念选错、定义漂移、同一概念冲突；不同义项被机械统一 |
| 中文表达 | 语法、指代、衔接、标点、影响理解的翻译腔 |
| 文体 | 语域、作者声音、礼貌程度、幽默/讽刺功能及过度润色 |
| 地区约定 | 目标字形/用词、数字格式和单位表达，且不改变实际数值 |
| 结构与标记 | 代码、链接、占位符、层级、记录与字幕对应关系 |

## 严重度按实际后果判断

- **Critical：** 会导致危险或根本相反的行动/结论，如义务主体反转、药物剂量错误、破坏性命令改变。必须修复；不能确认时说明具体疑义。
- **Major：** 明显误义、漏段、关键条件遗漏、重要术语错译或不可用的输出格式，显著影响理解或使用。
- **Minor：** 不改变含义的轻微语言、语气或排版问题。

不要仅凭领域标签判定严重度。也不要用总体“流畅”分抵消一个关键误译；同一问题不重复计数以夸大报告。

## 最终检查顺序

1. 先确认覆盖范围：正文、表格、注释、图注、脚注及用户指定的其他部分是否都有对应。
2. 对照关键语义：谁对谁做什么；否定、例外、限制、时间、引述和证据等级是否保留。
3. 核对数值与术语：数量级、正负号、币种、单位、有效位、百分比/百分点、概念一致性。
4. 检查输出能否使用：机器结构、链接、占位符和段落/cue 对应关系。
5. 再改善中文自然度、语气与节奏；确认润色没有引入事实。
6. 明确仍然缺失或无法消歧的内容，而非声称已经验证。

普通短句可一次完成；复杂长文或后果重大的关键句应增加对照深度。只有实际用途或具体疑义需要时，才提示相应专业复核；不要在每段纯翻译后机械追加免责声明。

## 自动化的证据边界

`scripts/check_translation.py` 对受保护片段做机械/启发式检查，可提示数字、URL、代码或占位符差异；JSON 模式还可辅助检查结构与非文本值。它不能判断否定、因果、证据强度、术语正确性、自然度或所有不可翻译字段。

- 差异可能是合法的本地化，也可能是真错误；先看上下文再处理。
- 检查通过只说明所启用的规则未发现差异，不能推出全文完整、格式全面有效或语义准确。
- 单元测试通过证明对应工具行为符合测试预期，不能充当翻译准确率。
- 人工/模型行为评测应记录用例、模型/环境、实际输出、评审理由和局限；不同模型的结果不能混为本 Skill 的固定能力。

## 用户要求审校报告时

每项列出：位置、原文片段、译文片段、严重度、问题理由、建议修订。区分“明确错误”“需语境确认”和“可选风格建议”。若用户要求分数，说明评分方法与样本范围；不自造权威分数或宣称未发生的术语检索、脚本运行、母语审校。
