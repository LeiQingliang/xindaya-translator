# 术语与专有名词治理

## 优先级

1. 当前用户明确指定、且没有重大歧义的术语映射。
2. 当前项目或组织提供的专业词汇表与历史译文（须确认上下文适用）。
3. 官方中文名称、标准化专业术语、领域通行译法。
4. 结合语境的保守译法；必要时保留源文术语及短释义。

不要将“官方”当作未经核查的标签。没有可靠依据就称“常见译法/可译作”，或保留英文。

## 文档级术语记录（建议结构）

| 字段 | 作用 |
| --- | --- |
| source_term | 源术语（大小写、原语形态） |
| target_term | 确认的简体中文译法或保留原文 |
| domain | 所属领域/产品 |
| definition | 语境定义与适用范围 |
| first_occurrence | 首次出现位置 |
| status | user-approved / contextual / unresolved |
| notes | 例外、缩写和容易混淆的词 |

## 一词多义处理

- `agent`：AI 领域常用“智能体”，法律语境可能是“代理人”，通用语境可能是“经纪人”。
- `token`：大模型语境多为“词元/Token”，鉴权中可能是“令牌”，金融中可能是“代币”。
- `model`：机器学习可指“模型”，商业或统计中根据具体语境区分。
- `fine-tuning`：ML 中“微调”，其他领域可能是“精细调整”。
- `harness`：软件生态里语义高度依赖上下文；优先保留原文并在必要时解释。

## 一致性与例外

- 同一**概念**在同一文档优先同一译法；不同义项不应被强行统一。
- 缩写首次可用“中文全称（ABBR）”；保留用户习惯时可直接使用缩写。
- 固定项目名、库名、函数名、命令和文件名不因翻译而重命名。
- 若用户词表与源文语境存在会改变实质含义的冲突，具体指出并请求必要澄清或给出透明的保守处理；不要悄悄换掉用户已指定的术语。

## 跨块一致性

- 在长文任务中维护轻量词汇表；每块翻译前加载已确认术语，翻译后只记录新增或更正项。
- 避免在多个代理之间让术语表分叉；多个译者必须使用同一确认版本并统一审校。
- 不将会话之外的私有术语表上传到未授权的外部服务。
