# 现代简体中文（zh-Hans-CN）风格规范

## 默认原则

- 以现代简体中文、中国大陆常用书面语为默认；用户指定其他目标地区时采用其要求。不要求文言化，忠实保留原文的正式程度、人物语气与专业密度。
- 术语准确、表达简洁、句式自然、段落有层次，避免无必要的翻译腔。
- 简体字形与地区用词是两个维度：源文繁体术语可在目标地规范下本地化，但专名不能盲目替换。

## 句式和衔接

- 长句允许拆分；不能拆散作用于同一命题的条件或例外。
- “对此”“因此”“然而”“同时”等连接词按逻辑添加，不为了顺滑而改变因果与对比关系。
- 可调整重复主语和代词，但必须保证指代明确。
- 被动结构可以主动化；涉及责任主体、受害或强调结果时保留相应语义。
- 不把原文所有名词化表达机械变成“对……进行……”。

## 术语与专名

- 使用已有术语表；无词表时选择权威/普遍使用的译法，不能因词面相似就强行翻译。
- 首次出现专有术语若中文不稳定，可用“中文（Source Term）”；后续适当省去括注。
- 软件名、模型名、变量名、库名通常保留原文大小写。
- 人名、国别、地名、历史称谓应与用户提供的写法保持一致；缺上下文时不凭空创造“官方译名”。

## 标点、字符与格式

- 中文叙述通常用 `，。；：！？（）《》“”`；代码、语法、URL、机器字段值和标识符保持有效；明确供人阅读的字段值按结构化内容规则翻译。
- 英文缩写与中文之间的空格可根据产品风格规范决定；本 Skill 不强制一种不可变排版风格。
- 书名、作品名是否用《》取决于体裁和既定译名；Markdown/富文本结构优先于排版个人偏好。
- 数字优先维持原文数值、有效位和百分比；不将 `5.0` 无理由变为 `5`，不把 `1,000` 当成 `1.000`。
- `15%` 与 `15 个百分点` 不是同一含义；`10 billion` 的中文数量级需准确（100 亿），不靠词形猜。
- 日期、时区、币种默认不换算；若只是改变显示格式，不能改变实际含义或精度。
- 中英文混排出现破坏机器可解析文本的风险时，优先保留源格式。

## 语体映射

| 源文风格 | 中文表现 |
| --- | --- |
| Plain / neutral | 简洁、中性、易懂 |
| Formal / business | 克制、准确、礼貌 |
| Academic | 客观、术语一致、证据强度不变 |
| Technical | 可操作、精确、少修辞 |
| Conversational | 自然口语，不公文化 |
| Literary | 意象与节奏适配，不擅自增加古风 |
| Humorous / sarcastic | 保留幽默机制与讽刺对象，不把反话当正话 |
| Intentionally awkward | 如不流畅是作者策略，应保留合理的“不自然感” |

## 禁止性示例

- 英文 `may improve` → 中文“必将显著改善”：无根据增强。
- 英文 `not all` → 中文“全部不”：否定范围改变。
- 技术 `server is down` → “服务器陷入长眠”：过度文学化。
- 原文口语 `I'm not sure.` → “鄙人对此尚未形成确定认知”：文体失配。
