# 领域专项翻译指南

## 领域识别

根据文本主题与目的，而不是个别关键词来确定领域。同一术语在不同领域可有不同译法。用户提供术语表、既有译文、组织风格规范时优先使用。领域交叉时按信息风险决定审校深度。

## 计算机、AI、软件工程

- 保护代码、命令、API、路径、环境变量、参数名、配置键、文件名、模型名称及协议名。
- `inference` 在机器学习中常为“推理”；`runtime` 常为“运行时”；`observability` 通常为“可观测性”。
- `RAG` 首次可用“检索增强生成（RAG）”；`fine-tuning` → “微调”。
- `agent` 在 AI 语境一般可译“智能体”或保留 `Agent`；`harness` 需看项目定义，不固定成“编排框架”。
- 不擅自改动 shell 命令、JSON key、包名和 API endpoint。
- README 与教程保持标题、代码块、序号、警告信息的精确对应；译文应能用于操作。

## 学术论文与科研报告

- 保留研究问题、假设、样本量、方法、实验条件、基线、评价指标、结果与局限。
- `suggest/indicate/may/be associated with` 不译成“证实/证明/导致”。
- 维护引用标签、方程编号、图表编号、p 值、置信区间及统计显著性。
- 摘要不自动替代正文；注释和背景知识不应混进译文。

## 财经、商业、经济与投资

- 区分 `revenue`（营收/营业收入）、`profit`（利润）、`net income`（净利润）、`cash flow`（现金流）、`gross margin`（毛利率），依财务报表口径确认。
- 保留金额、币种、数量级、% 与百分点（percentage points）的区别。`basis point` 译为“基点”；原文已有换算关系则完整保留，不自行添加换算。
- `guidance` 在财报语境可译“业绩指引”，不是笼统“指导”。
- 保留条件、风险提示、来源归因；财经观点不可译成保证回报的承诺。

## 法律、合同、合规

- 优先译明定义项、权利义务主体、管辖范围、条件、除外条款、时间要求和约束强度。
- `may/shall/must/should` 需按法律文本的管辖区、起草惯例和具体语境区分；没有通用一词对一词表。
- 重要定义与术语保持全篇一致；必要时标注原语以便法律专业人员核查。
- 不将解释性润色伪装成具有法律效力的正式译本。用途或具体疑义需要时提示专业复核；纯翻译不自动附加免责声明。

## 医学、生命科学、健康

- 精确保留剂量、单位、给药途径、频率、禁忌、适应证、警告和不确定性。
- 不自行更改治疗建议、研究结论或药物名称；无法确定缩略语时标示歧义。
- 逐项核对可能影响患者安全的关键句；无法消歧的剂量、缩写或说明应具体指出，而非自行修改原文或添加治疗建议。

## 新闻、时政、纪实

- 保留日期、主语、消息来源、直接/间接引语、指控与已证实事实的区别。
- 不把转述写成确定事实，不补入立场性形容词。
- 争议性专名按照用户约定和可核验译名处理；不虚构来源。

## 文学、散文、演讲

- 优先保留作者声音、人物关系、语气、意象、重复、排比、节奏和讽刺功能。
- 允许结构性重排；避免一律文言化、华丽化或消除方言人物特色。
- 无法保全双关时可选主含义并在注释模式标注双关；不要在默认纯净模式写长解释。

## 营销、品牌、公关

- 忠实版默认保留主张与事实；创意重构须用户明确要求“创译”或传播效果重构；`literary` 只表示文学表达，不自动授权改写事实或新增意象。
- 品牌主张、合规免责声明、数字和功能描述不能随意增强。
- 可根据用户提供的目标人群与品牌风格调整语气。

## UI、游戏、字幕与客服

- UI：优先操作清晰、短、术语一致；保留占位符、快捷键、控件名称和长度限制。
- 游戏：角色声音、世界观、人物称谓、技能术语全局一致；保留游戏机制相关数字。
- 字幕：遵循用户提供的时长/字符限制；不把两句信息无声合并丢失。
- 客服：保持礼貌等级及承诺范围，不擅自许诺退款、保修或结果。

## 保守翻译与解释之间的边界

如果领域术语没有明确等价词，优先“保留原文＋必要中文释义”；除非用户要求讲解，不扩写概念。领域风险高时，翻译不替代法律、财务或医疗专业判断。
