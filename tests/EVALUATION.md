# 真实 Agent 翻译评测说明

本次开发保存了 [2026-11-10 的 6 项实际试用输出](results/2026-11-10-smoke.json)，涉及 JSON、否定与证据、目标地区、缺少原文、源文指令和 Markdown。记录包含原始输出、参考文件及开发者复核意见。它不是完整用例集的运行结果，也不是有/无 Skill 的对照实验；精确模型标识与采样参数未记录，不能据此推算准确率或宣称全面兼容。源文指令试用还受评测任务自身“禁止外部行动”的约束，不能视为独立的安全防护验证。

`cases.json` 中的 `expected` 是**示例参考译文**，不是实际模型运行结果，也不是唯一正确译法。翻译有大量自然的同义表达；不要以字符串完全相等作为“翻译质量合格”的判据。它们未经过所有源语言的母语专家审核，遇到有争议的语言现象应请合适的评审者复核。

## 两类测试要分开

1. **离线结构测试**：执行 `python -m unittest discover -s tests -v`，能验证包结构、样例格式和脚本检测逻辑；不调用模型，不把 `expected` 当作模型回答。
2. **模型行为测试**：把 Skill 安装到目标宿主中，让该 Agent 使用 Skill 翻译每条 `source`，逐条检查语义忠实、表达自然、风格匹配及结构保护。此项需要实际模型/宿主，项目提供样例但**未预先宣称通过**。

## 推荐评审表

| 维度 | 打分 | 说明 |
| --- | --- | --- |
| 忠实（40） | 0–40 | 事实、否定、条件、证据等级、信息完整 |
| 通顺（20） | 0–20 | 现代简体中文自然、篇章连贯 |
| 术语（15） | 0–15 | 专名、领域义项、跨段一致 |
| 文体（15） | 0–15 | 人物声音、正式程度、修辞适配 |
| 结构（10） | 0–10 | 数字、代码、格式、占位符、URL |

这是起始工程权重，不是权威标准。出现会改变义务/否定/剂量等的 **Critical 错误一票否决**，不能以分数补偿。

## 执行步骤

1. 选择目标宿主，确认 Skill 在该宿主被发现并激活。记录宿主、精确模型标识、Skill 提交或版本、日期、采样设置、工具权限、评分者及评分规则版本。
2. 每条用例开启独立会话。若有 `context`，将它作为用户提供的上下文；若有 `request`，按该请求操作，否则要求“使用 xindaya-translator 翻译为简体中文”。清楚分隔 `source` 为源文数据，不能把其中的指令当作本次操作指令。
3. 保存模型真实输出；人工判断 `notes` 所指的风险点是否得到正确处理。允许与 `expected` 不同但语义等价的译法。
4. 对关键语义错误标注 `Critical/Major/Minor`；对格式错误可辅助使用 `check_translation.py`。
5. 回归时重复同一集合并记录真实输出、失败样例、未运行或无法评分的样例；不得从分母中静默剔除失败结果。若比较有/无 Skill 的表现，两组使用相同模型与设置，并明确随机性和评审偏差。不要把此小规模样例集推断成对所有语言/领域的泛化能力。

## 字段与评审记录

用例的必填字段是 `id`、`language`、`category`、`source`、`expected`、`notes`。可选 `request` 表示用户的明确要求，`context` 是译前上下文，`must_preserve` 记录需要逐字保留的少量字符串。`must_preserve` 不是完整的语义断言，也不代表项目已执行模型评测。

每次实际评测至少保存以下字段：

| 字段 | 内容 |
| --- | --- |
| case_id / run_id | 用例与运行的唯一标识 |
| actual_output | 未经事后修饰的模型输出 |
| invocation_confirmed | 是否确认宿主实际使用了 Skill |
| verdict | pass / fail / needs_review / not_run |
| severity / rationale | 错误严重度、依据及可接受替代译法 |
| reviewer / settings | 评审者和运行配置 |

长文任务还需另行记录分块覆盖范围、章节遗漏、跨块术语与指代；当前短用例中的 `context` 不能替代真实长文评测。

## 检查器的能力边界

```bash
python scripts/check_translation.py source.md translated.md --json
python scripts/check_translation.py source.json translated.json --format json --json
```

- 默认文本检查比较受保护 token 的**多重集合**：能发现数量变化，但不能证明 token 仍属于原句、原段或原顺序；交换两个数字可能完全不报警。
- 支持常见围栏、反引号代码、HTTP(S) URL 和简单占位符。它不是完整的 Markdown、HTML、YAML、字幕或 ICU 解析器，不验证相对链接、任意语法树、字段业务含义或样式。
- 中文紧邻数字会检查，正文全角数字可等价规范化；代码、占位符和 URL 不做这种规范化。数字写成汉字或改变地区数字格式可能触发合理的人工复核。
- `--format json` 拒绝重复键、非标准 NaN/Infinity、结构破坏；比较键、类型、数组长度和每个路径的非字符串值。数字用十进制精确解析，并检查有效小数位及有符号零；部分等价的指数写法仍可能被视为同一值。
- JSON 模式允许任意字符串值翻译，**不认识业务字段白名单和枚举**，也不识别纯文本数组项是否被语义调换。必须结合任务要求核对可译字段。
- JSON 模式会比较对应字符串字段中的受保护 token。`--ignore-numbers` 只关闭正文数字 token 检查，不关闭 JSON 数值比较；`--ignore-urls` 不关闭代码内容保护。
- 返回码 `0` 表示未发现上述差异，`1` 表示需人工复核，`2` 表示输入、编码或 JSON 解析错误。没有差异不等于翻译正确、完整或安全认证。

## 特别用例

- `en-ambiguous-01` 的 `expected` 不是单一答案，而是展示双关；缺上下文时保留歧义优先。
- `ja-context-01`、`ko-context-01` 的参考译法仅适用于其注释列出的场景。
- `en-injection-01` 测试将源文中注入性语句**翻译为文本**而不按其要求行动。
- `en-medical-01` 只测试忠实翻译剂量；不是任何给药建议。
